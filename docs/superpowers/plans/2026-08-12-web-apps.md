# Web Apps Deployed with the System (web-apps) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Use the declarative app mode (`.desktop` files with `Exec=google-chrome-stable --app=URL` + icons) to ship DeepSeek / Kimi / Gmail / GitHub as reproducible apps deployed with the dotfiles, and keep the scratchpad window behavior for DeepSeek / Kimi.

**Architecture:** 4 `.desktop` files go in `dotfiles/.local/share/applications/` and 4 256px PNGs in `dotfiles/.local/share/icons/hicolor/256x256/apps/`, deployed 1:1 by the existing dotfiles stage; the dotfiles stage of `install.sh` gains a desktop-entry/icon cache refresh; hyprland.lua gets window rules written with the measured `--app` URL-derived class names.

**Tech Stack:** bash (install.sh), Lua (hyprland.lua), the FDO `.desktop` / icon theme spec, ffmpeg (icon scaling), curl.

## Global Constraints

- Never run `./install.sh` (it mutates system state). Simulate deployment for local verification with **manual cp to `~/.local/share`**.
- Only two static checks: `shellcheck install.sh` and `luac -p dotfiles/.config/hypr/hyprland.lua`.
- Do not run `stylua`; hyprland.lua keeps 4-space indentation + aligned `=`.
- `.desktop` files omit `StartupWMClass` (Chrome ignores it under Wayland; writing it would mislead).
- Comments are in Chinese.
- All icons are 256x256 PNGs stored in `hicolor/256x256/apps/`; the `.desktop` `Icon=` values use the basename (icon name).
- App URLs (verified reachable):
  - DeepSeek `https://chat.deepseek.com`
  - Kimi `https://www.kimi.com` (`kimi.moonshot.cn` 301-redirects here)
  - Gmail `https://mail.google.com`
  - GitHub `https://github.com`

### Task 5: hyprland.lua window rules (DeepSeek / Kimi scratchpad)

**Files:**
- Modify: `dotfiles/.config/hypr/hyprland.lua` (after the existing Chrome PWA rule block, before `suppress-maximize-events`, around lines 300-301)

**Interfaces:**
- Consumes: the DeepSeek / Kimi classes measured in Task 4 Step 4 (replace `<DEEPSEEK_CLASS>` / `<KIMI_CLASS>` below with the measured values)
- Produces: two window rules; DeepSeek / Kimi app windows float into special workspaces

- [ ] **Step 1: Add two window rules using the measured classes**

Class names measured in Task 4 (verbatim, do not change):
- DeepSeek: `chrome-chat.deepseek.com__-Default`
- Kimi: `chrome-www.kimi.com__-Default`

Insert after the existing `float-kimi` rule:

```lua
-- Web apps (app mode; class names are derived from the --app URL, measured values above)
hl.window_rule({
  name = "float-deepseek-web",
  match = { class = "^(chrome-chat\\.deepseek\\.com__-Default)$" },
  float = true,
  size = "1200 800",
  center = true,
  workspace = "special:deepseek silent",
})
hl.window_rule({
  name = "float-kimi-web",
  match = { class = "^(chrome-www\\.kimi\\.com__-Default)$" },
  float = true,
  size = "1200 800",
  center = true,
  workspace = "special:kimi silent",
})
```

> Note: Hyprland's `match.class` is regex-based (same style as the existing `io\.github\.xiaoyifang\.goldendict_ng` rule); `\.` escapes the dot and `-` is literal. The `__` in the class names are URL-derived characters kept as-is.

- [ ] **Step 2: luac check**

Expected: no output (syntax OK).
